## 1. Архитектура системы (Глава 3)

### Положение автореферата
> «Система использует клиент-серверную архитектуру с разделением на 3 уровня: презентационный уровень (веб-интерфейс), бизнес-логику (API и модели) и уровень данных (обработка временных рядов).»

### Оценка кода ✅ СООТВЕТСТВУЕТ

Архитектура в точности реализует трёхуровневую схему:
- **Уровень 1 — Презентационный:** `frontend/index.html` + `frontend/style.css` — полноценный веб-интерфейс с графиком, загрузкой файлов, выбором модели и горизонта прогноза.
- **Уровень 2 — Бизнес-логика:** `backend/main.py` — FastAPI-сервер с эндпоинтами `/upload`, `/forecast`, `/export`, `/models`, `/health`.
- **Уровень 3 — Данные/модели:** пакет `models/` (`hybrid_model.py`, `sarima_xs.py`, `xgboost_model.py`, `timellm_gguf.py`) + `backend/llm_expert.py`.

### Положение автореферата (процесс прогнозирования)
> «1. Загрузка файла .csv/.xlsx с двумя колонками: дата, значение. 2. Передача данных серверной части. 3. Начало обучения. 4. Автоматический подбор параметров. 5. Обучение и генерация прогнозов. 6. LLM-эксперт вносит коррекции. 7. Возврат прогноза в .csv/.xlsx.»

### Оценка кода ✅ СООТВЕТСТВУЕТ ПОЛНОСТЬЮ

Все 7 шагов реализованы в `backend/main.py`:
- Шаг 1–2: эндпоинт `POST /upload` с парсингом CSV/XLSX, определением колонок, поддержкой русских дат.
- Шаг 3–5: эндпоинт `POST /forecast`, обучение выбранной модели через `.fit(values_array)`.
- Шаг 6: блок LLM-коррекции — вызов `llm_expert.correct_forecast(...)`, вычисление Δ_LLM.
- Шаг 7: эндпоинт `GET /export` с экспортом в CSV и XLSX.

## 3. Математические формулы (Глава 2)

### 3.1 Формула 2.6: Корректирующий коэффициент α(n)

**Автореферат:**
```
α(n) = 1 + ln(20/n)  при n < 20
α(n) = 1.0           при n >= 20
```
*Примеры из текста: при n=30→15 коэффициент растёт на 83%, при n=15→10 на 27%.*

**Код (`models/hybrid_model.py`, строки 160–172):**
```python
def _alpha_correction(self, n):
    if n < 20:
        return 1 + np.log(20 / n)
    return 1.0
```

**Оценка: ⚠️ ЧАСТИЧНОЕ НЕСООТВЕТСТВИЕ**

Формула реализована корректно, однако **в тексте автореферата** приводятся примеры, которые соответствуют формуле с `T_ref=30`, а не `T_ref=20`:
- «при n=30→15 рост 83%»: `ln(30/15)=0.693` → рост ~69%, а не 83%
- Если же брать `T_ref=20`: `ln(20/5)=1.386`, `ln(20/15)=0.288` — значения иные.

Числовые примеры в тексте автореферата (83% и 27%) **не воспроизводятся** ни при `T_ref=20`, ни при `T_ref=30`. Вероятно, в тексте приведены примеры из более ранней версии формулы. **Рекомендуется синхронизировать числовые примеры в тексте с реализованной формулой** или добавить пояснение.

### 3.2 Формула 2.7: Экспоненциальные веса ER_i(t)

**Автореферат:**
```
ER_i(t) = λ × ER_i(t-1) + (1-λ) × NormMAE_i,   λ = 0.8
```

**Код (строки 291–295):**
```python
self.error_history[model] = (
    self.decay_factor * self.error_history[model] + 
    (1 - self.decay_factor) * normalized_errors[model]
)
```

**Оценка: ✅ ПОЛНОСТЬЮ СООТВЕТСТВУЕТ**

Константа `LAMBDA = 0.8` явно объявлена (строка 69). Нормализация ошибок через `scale = max(std, |mean|*0.1, 1.0)` — дополнительная инженерная мера для устойчивости, корректно не описана в автореферате как отдельная формула, но логически оправдана и не противоречит модели.

### 3.3 Формула 2.5/2.11: Веса моделей w_i(t)

**Автореферат:**
```
w_i(t) = exp(-β × ER_i(t) × α(n)) / Σ exp(...)
```
где β = 1.2

**Код (строки 297–312):**
```python
exponent = -self.BETA * self.error_history[model] * alpha * kappa
exp_weights[model] = np.exp(exponent)
...
self.weights[model] = exp_weights[model] / total
```

**Оценка: ⚠️ ДОПОЛНИТЕЛЬНЫЙ МНОЖИТЕЛЬ κ(n)**

Код включает `kappa = self._kappa_correction(n)` в вычислении экспоненты (`alpha * kappa`). Коэффициент κ(n) описан как «Формула 2.12» в комментарии, однако **в тексте автореферата формула 2.11 не содержит κ(n)** — описан только α(n). Коэффициент κ(n) отсутствует в публичном тексте автореферата.

**Рекомендация:** Убедиться, что κ(n) явно описан в Главе 2 диссертации (не только автореферате), или добавить его в финальный текст.

### 3.4 Формулы 2.8/2.9: Коррекция смещения Δ_bias(n, h)

**Автореферат:**
```
Δ_bias(n, h) = γ × h × σ̂ × √(1/n + 1/T)
где γ = 0.15, T = 30 (теоретическая длина)
```

**Код (строки 223–245):**
```python
GAMMA_BIAS = 0.15
T_NORMAL = 100   # ← РАСХОЖДЕНИЕ! В автореферате T=30, в коде T=100
...
uncertainty_factor = np.sqrt(1/n + 1/self.T_NORMAL)
delta = self.GAMMA_BIAS * h * sigma * uncertainty_factor
```

**Оценка: ❌ СУЩЕСТВЕННОЕ РАСХОЖДЕНИЕ**

В тексте автореферата явно указано:
> «T — теоретическая длина среднего ряда (T = 30)»

В коде константа `T_NORMAL = 100`. Это **прямое несоответствие** числового параметра. Влияние:
- При T=30 и n=15: `√(1/15 + 1/30) = √(0.0667+0.0333) = 0.316`
- При T=100 и n=15: `√(1/15 + 1/100) = √(0.0667+0.01) = 0.277`

Коррекция смещения при T=100 **на ~12% меньше**, чем при T=30, указанном в автореферате.

**Необходимо исправить:** Установить `T_NORMAL = 30` в соответствии с автореферератом, или изменить текст диссертации на T=100 с соответствующим обоснованием.

### 3.5 Формула 2.13/2.14: Робастная обработка выбросов (MAD)

**Автореферат:**
```
μ̂ = median(X)
MAD = median(|X - μ̂|)
σ̂ = MAD / 0.6745
Порог: |X(t) - μ̂| ≤ 2.5 × σ̂
```

**Код (строки 120–155):**
```python
mu_robust = np.median(data)
mad = np.median(np.abs(data - mu_robust))
sigma_robust = mad / self.MAD_SCALE  # MAD_SCALE = 0.6745
threshold = self.MAD_THRESHOLD * sigma_robust  # MAD_THRESHOLD = 2.5
# Winsorization при превышении порога
```

**Оценка: ✅ ПОЛНОСТЬЮ СООТВЕТСТВУЕТ**

Все константы (0.6745, 2.5) и алгоритм точно реализованы.

### 3.6 Формула 2.17: Адаптивный вес LLM-эксперта w_LLM(n)

**Автореферат:**
```
w_LLM(n) = линейная зависимость от n в диапазоне [n_min, n_max]
```
*(точная формула в автореферате описана качественно: «линейная зависимость... плавное увеличение доверия»)*

**Код (строки 202–218):**
```python
def _w_llm(self, n):
    if 5 <= n <= 20:
        return 0.15 + 0.35 * (n - 5) / 15
    elif n > 20:
        return 0.5
    else:
        return 0.1
```

**Оценка: ✅ СООТВЕТСТВУЕТ**

- При n=5: w_LLM=0.15 (минимум для коротких рядов)
- При n=20: w_LLM=0.50 (максимум)
- Линейный рост реализован корректно.

### 3.7 Формула 2.18: Итоговый прогноз

**Автореферат:**
```
Ŷ_final(t+h) = Ŷ_ensemble(t+h) + Δ_bias(n,h) + w_LLM(n) × Δ_LLM(t+h)
```

**Код (строки 619–628):**
```python
final_forecast = ensemble_forecast + bias_corrections + w_llm * delta_llm
```

**Оценка: ✅ ПОЛНОСТЬЮ СООТВЕТСТВУЕТ**

Формула реализована дословно. Логика передачи Δ_LLM через `llm_correction` в `backend/main.py` (строки 686–689) корректна:
```python
corrected_forecast_llm = correction_result['corrected_forecast']
llm_correction = corrected_forecast_llm - preliminary_forecast  # Это и есть Δ_LLM
```

## 4. LLM-Эксперт (Глава 3)

### Положение автореферата
> «LLM-эксперт – большая языковая модель, обогащённая внешним контекстом. Алгоритм включает: обработку источников пользователя, формирование выжимок, интеграцию прогнозов, формирование структурированного запроса, генерацию нескольких ответов для усреднения, пояснения к прогнозу.»

### Оценка кода ✅ СООТВЕТСТВУЕТ (с замечаниями)

**Реализовано полностью:**
- Загрузка HTML из веб-источников (`_fetch_web_context`) с таймаутом 15 с, парсингом HTML-тегов (`HTMLTextExtractor`), извлечением ключевых фактов (`_extract_key_facts`).
- Формирование структурированного промпта (`_build_user_prompt`) с историческими данными, статистикой, трендом, прогнозами и внешним контекстом.
- Системный промпт (`_build_system_prompt`) с ролью эксперта и чёткими инструкциями по диапазону коэффициентов (0.8–1.2).
- Парсинг JSON-ответа с fallback на извлечение чисел из текста.

**Замечание — «несколько генераций»:**
> В автореферате: «производится несколько генераций с различными параметрами»

В коде выполняется **только один вызов** `_call_yandex_gpt(...)` без усреднения нескольких ответов. Это означает, что важная часть алгоритма из автореферата (ансамблирование ответов LLM) **не реализована**.

**Рекомендация:** Добавить цикл из 2–3 вызовов с разной температурой и усреднением коэффициентов коррекции, либо убрать это утверждение из текста диссертации.

**YandexGPT vs «большая языковая модель»:**  
Используется `yandexgpt-lite` через OpenAI-совместимый API Yandex Cloud. Это коммерческая LLM, что полностью соответствует описанию «коммерческих LLM» в публикациях автора (статья 2025 г.).

## 7. Ограничения длины временного ряда

### Положение автореферата
> «при ограничениях: 1. min(n) ≥ 10; 2. max(n) ≤ 30»

### Оценка кода: ⚠️ ЧАСТИЧНОЕ НЕСООТВЕТСТВИЕ

**Граничное условие:**  
В `hybrid_model.py` строка 411:
```python
need_validation = n > 10  # строго больше 10
```
По автореферату min(n) = 10, т.е. при n=10 валидация должна выполняться (`n >= 10`). Код пропустит валидацию при n=10.

**Верхняя граница:**  
Нет явной проверки `n <= 30`. Код работает и при n=34 (как видно из `results.json` — inflation, usdrub, brent). Это корректное расширение, но входит в противоречие с декларируемым ограничением «max(n) ≤ 30».

**Рекомендация:**
```python
need_validation = n >= 10  # исправить с > на >=
```
Либо уточнить в тексте, что ограничение носит рекомендательный характер.
